## Deviations
- Enqueue condition: also requires the status to differ from the previous one (inside the existing `previous_status != new status` block, next to `alert_service`). A message-only change would otherwise say "updated to X" with X unchanged. The contract says `changed` and `previous_status`.
- Silent flag is applied inside `ensure_service.ensure_tracking` (covers the job and the desk Generate action's sync call) and again in `ensure_tracking_job`. The helper restores the previous flag value, so nesting is safe. Flag is read/written through `frappe.flags[...]`.
- Whatsapp Default validate: with the switch on it requires `whatsapp_account`, the `Visa Tracking Update` row and a valid URL. I did not require `enabled` itself (the send already skips when the zone is not enabled; the existing enabled rules still run when `enabled` is on). Open question below.
- Tracker URL button suffix: path (leading slash stripped) plus query; empty gives `?ref=whatsapp`. Fragment dropped.
- Visa Tracker Settings "General" tab dropped (would be empty), as the contract allows. Existing section breaks were reused with relabels (`feature_and_extraction_section` = Extraction, `lifecycle_section` = Status, `public_tracking_section` = Access). Passport Extraction reused `source_section`, `processing_section`, `passport_values_section`, `mrz_section`, `audit_section` (relabelled "Raw OCR and result").
- No `field_order` Property Setter exists for either doctype (checked the_visaguy fixtures; passport_extractor has no fixtures), so nothing to remove. The JS and list script reference no field by position or section.
- `settings = frappe.get_single(...)` lines in test_public_api.py are left in place; the variable is now unused in some tests.

- Correction (c5f25d3): `lifecycle_service.enqueue_client_status_recompute` and `jobs.recompute_client_status` take `silent=False`. The enqueue passes `silent=True` when asked or when `frappe.flags.visa_tracking_silent` is set (the ensure/create path); the job then runs inside `silent_status_updates()`. The Process File save hook stays non-silent. `ensure_service` itself calls the recompute synchronously (already inside the flag), so it has no other deferred status path. Not covered: a recompute queued by the extraction-verified handler path (outside any ensure run) is still non-silent. Whatsapp Default `enabled` is not required at save time (owner answer).
