B1. Rewrite `waflo/waflo/flow/rate_limiting.py` to use an atomic counter.

    Current design stores a compound dict {"count": N, "window_start": T} via
    `frappe.cache().set_value(...)`, then reads-modifies-writes it in Python. That is
    inherently non-atomic (D4) and duplicates the TTL with a stored window_start (D5).

    New design — fixed window, atomic:
        key = f"waflo:rl:{account}:{mobile_no}"
        count = frappe.cache().incr(key)
        if count == 1:
            frappe.cache().expire(key, window_seconds)

    `incr` is atomic so concurrent workers serialise. Setting the TTL only when the counter
    returns 1 starts the window at the first request and removes the need for window_start.
