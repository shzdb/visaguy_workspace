TASKS:

E1. D8 — error handler masks the original error. In `waflo/waflo/messaging/send.py`, the
    `except` around the send does:
        frappe.get_doc({... "meta_data": frappe.flags.integration_request.json()}).insert(...)
    `frappe.flags.integration_request` only exists once a request has actually been issued.
    When the failure happens earlier (missing token, unresolved template, bad payload) this
    raises AttributeError inside the handler and the ORIGINAL exception is lost.
    Guard it. The original exception must always be logged with a full traceback
    (`frappe.get_traceback()`), and the notification-log insert must never be able to mask it.

E2. D9 — missing template not guarded. `frappe.db.get_value("WhatsApp Templates",
    template_name, "actual_name")` returns None for an unknown template, and the payload then
    goes out with `"name": null`. Fail fast with a clear, actionable error instead. Do not
    send a null template name.

E3. D10 — log spam. `frappe.log_error("WhatsApp API URL AND INDEX", ...)` is called inside the
    per-button loop on EVERY send that has buttons. Remove it. It is leftover debug output in
    a production path and it buries real errors in the Error Log.

E4. D11 — `use_flow` collides with `button_url_map`. The flow button is appended at
    `index "0"`, but when `button_url_map` is also supplied its first entry is already
    `index "0"`. Decide and implement: either reject the combination with a clear error, or
    offset the flow button index past the URL buttons. Justify your choice in the log.

E5. N2 — continuing path assumes a non-null reference doc. In `processor.py`,
    `context_doc = frappe.get_doc(active_doc.reference_doctype, active_doc.reference_name)`
    runs unguarded, but `create_active_flow` permits both to be None. Guard it the same way
    the new-flow branch already does (`if ref_doctype and ref_name else None`).

E6. N4 — `send_default_message` reads `wf_account_settings.header_video` when
    `header_type == "Video"`, but `WF Account Settings` has no such field — it defines
    `header_image`, `header_attachment`, `header_text`. Use the correct field. Check the
    DocType JSON to confirm which field is intended for video before choosing.

E7. D6 — remove `limit_after` from `WF Settings`:
    - remove the field from `wf_settings.json` (both the `field_order` list and the `fields`
      array — miss one and the DocType will not load)
    - add a Frappe patch to drop the stale column/property on existing sites, registered in
      `patches.txt`. Follow the existing patch conventions in this repo if any exist; if
      `patches.txt` does not exist, create it in the standard Frappe location.
    - confirm nothing in Python reads it before removing.
