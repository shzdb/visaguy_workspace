IMPORTANT CONTEXT — how limiting already works, so you do not double-count:

`_process_incoming_whatsapp_message` in processor.py already gates INBOUND messages:
it calls `is_rate_limited(...)`, and if limited it marks the message `custom_rate_limited`
and returns. The flow paths then call `increment_rate_limit(...)` explicitly after sending.

So flow-driven sends are ALREADY accounted for. If you naively add a check+increment inside
`send_whatsapp_template`, flow sends will be counted twice. Design around this.
